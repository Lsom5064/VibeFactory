# 호스트·서버 성능 검토 및 검증 — 2026-10-02

## 범위

`vibefactory/`의 API 클라이언트, 채팅 갱신·캐시, 다운로드, 백그라운드 상태 감시,
UI 편집 화면·이미지 처리와 `server/`의 상태·타임라인 조회, XML API, 파일 응답 경로를 검토했다.
사용자의 터치 순서, 버튼, 도구, 설명 입력 규칙, 서버 주소 및 설치 정책은 유지한다.
생성 에이전트의 프롬프트, 모델, APK 빌드 정책은 이번 변경 범위에 포함하지 않는다.

## 적용한 개선

| 위치 | 확인한 비용 | 변경 |
| --- | --- | --- |
| `HostAppConfig.kt` | 화면·상태 감시·다운로드마다 독립 연결 풀이 생겨 서버 소켓을 공유하지 못함 | 공통 OkHttp 연결 풀 사용. 각 클라이언트의 Dispatcher와 기존 타임아웃은 유지 |
| `UiAnnotationEditorActivity.kt` | XML 조회, 로컬 초안 읽기, 서버 초안 조회를 순차 실행 | 독립적인 읽기를 함께 시작. 원격 초안 실패 시 기존 로컬 복구 정책 유지 |
| 같은 파일 | 리소스 XML 분석 및 첨부 썸네일 파일 읽기·디코딩이 메인 스레드에서 실행 | XML 분석은 Default, 썸네일은 IO에서 처리. View 갱신은 메인 스레드에서 실행 |
| 같은 파일 | 이전 화면 요청이 나중에 끝나면 ViewModel 초기화에 영향을 줄 수 있음 | 현재 조회 세대인지 확인한 뒤 초기화. 취소 예외는 정상 전파 |
| `LibraryActivity.kt` | 라이브러리 JSON 파일 읽기·분석이 메인 스레드에서 실행 | IO에서 읽은 결과를 기존 UI로 표시 |
| `server.py` | 표시하지 않는 원시 Agent/앱 LLM 이벤트도 큰 본문을 정제하고 JSON을 분석 | 기존 숨김 판정을 본문 처리 전에 실행. DB의 원본 이벤트는 그대로 보존 |
| 같은 파일 | 상태 결과 JSON을 한 요청에서 두 번 분석 | 한 번 읽은 상태를 대화 상태 계산에도 전달 |
| 같은 파일 | 새 이벤트가 없는 폴링에서도 첨부 목록을 조회 | 커서 이후 이벤트가 없으면 첨부 조회 생략 |
| `json_response_compression.py` | XML 등 큰 JSON 응답을 그대로 전송 | 2KB 이상인 완결된 GET JSON 응답을 gzip 지원 클라이언트에 압축 전송. 압축은 스레드 풀에서 실행 |

압축은 200 JSON 응답에 한정하며 파일·이미지·APK, Range 요청, 206 응답, 쓰기 요청,
HEAD, 기존 Content-Encoding 및 스트리밍 응답은 그대로 전달한다.
이미 압축된 데이터보다 커지는 경우 원본을 전달한다. Content-Length와 Vary를 함께 처리한다.

## 검증

- 서버 현재 작업 트리: 전체 테스트 239개 통과.
- 커밋 대상만 적용한 HEAD 복사본: 전체 서버 테스트 199개 통과.
- 호스트: 단위 테스트 173개, debug APK 및 Android 테스트 APK 빌드 통과.
- 초기 빌드에서 기존 Kotlin 증분 캐시의 참조 오류가 발생했으나 `-Pkotlin.incremental=false`로 전체 재컴파일하여 해결. 이후 일반 증분 빌드도 통과.
- 실기기 Samsung SM-S908N: 테스트 50개 통과. 이동·추가·좌우 삽입·끝 스크롤·확대·초안 저장/복구·편집 성능 회귀 검증 포함.
- 실제 운영 채팅방의 XML 편집 화면을 기존 로그인 상태에서 조회하여 렌더링 확인. 테스트 관찰기를 통해 XML 조회와 초안 조회가 함께 시작되는지 검증.
- 별도 포트 18092, 임시 Task DB·앱 데이터 DB·workspace를 사용한 서버에서 Android Retrofit DTO, gzip 자동 복원, 타임라인 커서 응답을 확인.
- APK·Range 전송 계약은 서버 API 테스트로 확인. 이 작업에서 생성 APK를 새로 만들거나 생성 소요 시간을 측정하지 않았다.
- 동일한 디버그 서명을 확인하고 `adb install -r`로 호스트 업데이트. 기존 채팅방과 다운로드/앱 열기 상태 유지 확인.
- 업데이트 전후 APK의 `res/` 및 `resources.arsc` 914개 항목을 바이트 비교했으며 모두 동일. 아이콘·레이아웃·문구 변화 없음.

## 추가로 고려할 사항

- 상태 감시 서비스는 여러 Task를 순차 확인한다. 병렬화를 하려면 알림·SharedPreferences 갱신의 동시성까지 함께 검토해야 한다.
- 채팅의 원격 이미지 로더는 메모리 캐시가 있지만 진행 중인 동일 요청의 합치기는 없다. 중복 요청 수를 계측한 뒤 개선할 수 있다.
- 최초 실행의 레거시 채팅 마이그레이션은 별도의 비용이다. 일반 채팅 저장·복구는 이미 백그라운드에서 처리한다.
- XML API의 서버 캐시는 리비전·소스 변경·리소스 해시와 일관되게 무효화해야 한다. 단순 시간 캐시는 409 충돌이나 오래된 미리보기의 원인이 될 수 있어 추가하지 않았다.

운영 중인 로컬 서버는 자동 재로딩 없이 실행 중이다. 실행 프로세스에 대한 반영은 재시작 후 가능하며,
사용자 운영 서버를 임의로 재시작하지 않는 프로젝트 지침에 따라 별도로 확인한다.
