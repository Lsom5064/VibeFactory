# 호스트 편집 흐름 개선 및 점검 — 2026-10-01

## 사용자 동작

- 추가·모양/기능 변경의 스케치 화면에 확대, 축소, 현재 배율, 전체 보기 버튼을 제공한다.
  두 손가락 확대·이동은 1–4배 범위에서 동작한다. 보기 배율은 저장하는 선·이미지 좌표를 바꾸지 않는다.
- 도구 안내는 미리보기 위에 겹쳐 띄우지 않고 별도 공간을 차지한다.
- 이동 도구에서 UI를 터치한 채 바로 드래그하거나, 먼저 터치해 선택한 다음 목적지로 드래그할 수 있다.
  손을 떼어도 여러 번 다시 드래그해 위치를 조정할 수 있다. 도구 안내의 `추가하기`를 눌렀을 때만
  기존 설명 팝업을 열며 팝업에서 확정해야 표시를 저장한다. 취소하면 이동 미리보기를 복원한다.
- 최초 생성 프롬프트를 받은 뒤 같은 채팅방에서 내용을 추가·변경하면 프롬프트를 다시 정리한다.
  최종 생성은 최신 프롬프트 확인 화면의 `전송하기`에서 시작한다.
  요청 처리 중 중복 전송과 이전 검토 버블의 제출을 막는다.

## 코드 점검과 정리

- 기존 스케치 편집기를 공통으로 사용하고 확대 컨트롤을 별도 View로 분리했다.
- 이미지 디코딩이 취소되거나 일부 이미지 로딩이 실패하면 아직 소유권을 넘기지 않은 비트맵을 해제한다.
- 대상 탐색 시 캔버스 조회·크기 계산을 요소별 반복문 밖으로 옮겼다.
- 도구 안내 문구, 이동 팝업 버튼명과 기존 선택적 E2E 테스트의 화면 이름을 맞췄다.
- 저장 좌표, 이동/추가 미리보기 재배치, UI 초안 충돌 처리, 호스트·서버의 검토 프롬프트 계약을 함께 확인했다.
- 기존 로컬 편집 도구 변경과 그에 필요한 서버 연동을 커밋에 포함한다.
  별도 AWS 설정, 외부 데이터 접근 일반화, 서버 빌드 복구 변경 및 운영 서버용 수동 테스트 파일은 로컬에 보존한다.

반복 이동 조정·화면 재생성 이후에도 안내의 버튼을 누르기 전까지 팝업이 열리지 않는 동작과 이동 팝업 확정,
가장자리 스크롤, 여러 이동 표시 사이 삽입, 추가 영역 재배치, 취소·되돌리기·화면 재생성을 검증했다.
기존 APK와 같은 서명임을 확인한 후 `adb install -r`로 업데이트했으며 앱을 삭제하거나 데이터를 초기화하지 않았다.

서버 검증은 임시 DB/workspace를 사용했다. 프롬프트 구체화 검증은 명세 분석 응답을 모의 처리하고
실제 API·DB·빌드 진입 조건을 검사했다. 이번 작업에서 실제 LLM으로 새 앱을 생성하는 E2E 검증은 하지 않았다.
